# Data Testing

Load this reference when writing or reviewing a test for a repository, remote data source, DAO, migration, DataStore, `PagingSource`, or dispatcher wiring. Composable and UI-test mechanics belong to the `compose-feature` skill, not here.

1. **The remote source takes `HttpClientEngine` as a constructor parameter; production and tests share one `createHttpClient` factory, and tests swap in `MockEngine`.** [non-negotiable] The Ktor testing guide builds the client wrapper around an injected engine and passes `MockEngine` in tests (`https://ktor.io/docs/client-testing.html`). A remote source that constructs its own engine cannot be tested without the network. *Prevents:* HTTP tests that hit the real backend.
2. **`HttpClient` and its engine are DI `single`s; tests replace the engine binding, never the call sites.** [non-negotiable] One client instance per app; the test graph binds `MockEngine` where production binds the platform engine. A per-screen client multiplies connection pools and makes the mock incomplete. *Prevents:* unmocked network paths in tested features.
3. **Unit-test each `PagingSource` with `LoadParams.Refresh` assertions covering page success and the network-error path.** [non-negotiable] Construct the production `NotesPagingSource` directly, call `load` with `LoadParams.Refresh`, and assert `LoadResult.Page` data plus `prevKey`/`nextKey`, then repeat with the remote source failing and assert `LoadResult.Error`. The paging path never enters `launchGuarded` (SKILL.md rule 6), so this test is the only gate on page failures. *Prevents:* page errors that surface only on device.
4. **Test DAOs against an in-memory database built with the project's database builder plus the bundled test driver.** [non-negotiable] Insert through the DAO, read back through the DAO, assert the Catalog rows round-trip; close the database after each test. A DAO tested against a file database leaks state between tests and order-dependence follows. *Prevents:* order-dependent DAO tests.
5. **Test every migration with `MigrationTestHelper`: create at the old version, insert rows, run the migration, validate schema plus data.** [non-negotiable] The helper reads exported schemas, so schema export stays enabled (`https://developer.android.com/training/data-storage/room/migrating-db-versions`). Seed a Notes row at version N, migrate to N+1, assert the row survives with its fields intact. *Prevents:* migrations that pass schema validation but drop user data.
6. **Test DataStores through the production factory with a per-test temp directory.** [default] Each test gets its own directory, writes Notes settings through the repository, reads them back, and deletes the directory. A shared file across tests is shared mutable state. *Prevents:* DataStore tests that pass alone and fail together.
7. **Inject every dispatcher production code uses; run every async test in `runTest` on a test dispatcher.** [non-negotiable] Production defaults to `StandardTestDispatcher` semantics in tests: queued coroutines run only when the test advances time (`advanceUntilIdle`, `runCurrent`), which mirrors production scheduling (`https://kotlinlang.org/api/kotlinx.coroutines/kotlinx-coroutines-test/kotlinx.coroutines.test/-standard-test-dispatcher.html`). Reach for `UnconfinedTestDispatcher` only when eager execution simplifies a stateless test (`https://kotlinlang.org/api/kotlinx.coroutines/kotlinx-coroutines-test/kotlinx.coroutines.test/-unconfined-test-dispatcher.html`). `runTest` skips delays and owns virtual time (`https://kotlinlang.org/api/kotlinx.coroutines/kotlinx-coroutines-test/kotlinx.coroutines.test/run-test.html`). A hardcoded `Dispatchers.IO` in production ignores the test scheduler and the test becomes timing-dependent. *Prevents:* flaky async tests.
8. **Write one canonical in-memory `Fake` per repository interface with seeding helpers; fakes carry state, mocks verify interaction.** [non-negotiable] `FakeNotesRepository` holds a seeded list, throws a settable error, and backs ViewModel tests through constructor injection. ViewModel tests that need a DAO use a `MutableStateFlow`-backed fake DAO. Reach for a mock only to verify one specific interaction, never to stub state. No Mockito, no MockK. Substitute Android framework classes through Robolectric shadows only as a last resort, and never verify framework or library internals. Turbine is not in the kit: collect effects and flows with `backgroundScope` into a list and assert the list (`https://github.com/cashapp/turbine` documents the library the kit deliberately excludes). *Prevents:* mock-fragile tests that break on refactor.
9. **Keep unit layers hermetic; mocked network appears at most at the feature layer.** [non-negotiable] Repository, mapper, DAO, and ViewModel tests run offline with fakes. Only a feature-level test may stand up `MockEngine`, and even there the remote source under test is the production one. A mock at every layer tests the mocks, not the code. *Prevents:* a green suite around a broken integration.
10. **Never mark production `open` for tests.** [non-negotiable] No `internal open class`, no open method added to enable subclassing in tests. Tests fake the repository interface; HTTP tests use `MockEngine` against the production remote source (CONTRACT_BRIEF §5.6). An `open`-for-tests class compiles but invites subclasses that bypass the contract. *Prevents:* test-only production shapes that rot silently.

## Red flags

| Thought | Reality |
|---|---|
| "I'll build the `HttpClient` inside the remote source; the test can use a real server." | No. Rule 1: engine is a constructor parameter, `MockEngine` swaps in. A self-built client is untestable offline. |
| "I'll `try/catch` the page load in the repository test and assert null." | No. SKILL.md rule 5: failures propagate. Assert `LoadResult.Error` from the `PagingSource`, never a swallowed null. |
| "I'll test the migration by opening the latest schema only." | No. Rule 5: create at the old version, migrate, validate data. Latest-schema-only tests never exercise the migration path. |
| "I'll share one DataStore file across tests; setup is faster." | No. Rule 6: per-test temp dir. Shared files are shared mutable state. |
| "I'll use `UnconfinedTestDispatcher` everywhere; tests need no advancing." | No. Rule 7: default to `StandardTestDispatcher` semantics, which mirror production queuing. Eager execution hides ordering defects. |
| "I'll mock the repository with Mockito; it is less code than a fake." | No. Rule 8 and SKILL.md rule 5 territory: fakes carry state, no mocking library. Mocks of state-bearing collaborators encode implementation, not behavior. |
| "I'll add Turbine; `awaitItem` reads cleaner." | No. Rule 8: Turbine is not in the kit. Collect with `backgroundScope` and assert the list. |
| "I'll mark the remote source `open` so the test can override one method." | No. Rule 10: never open production for tests. Fake the repository; test HTTP through `MockEngine`. |

## Verification

- [ ] Every remote source constructor takes `HttpClientEngine`: `grep -rn "HttpClientEngine" --include='*.kt' <data-root>` covers each remote source: yes or no.
- [ ] No remote source constructs its own engine: `grep -rn "HttpClient(" --include='*.kt' <data-root>` shows only the shared factory: yes or no.
- [ ] Every `PagingSource` has a test asserting `LoadResult.Page` and `LoadResult.Error` via `LoadParams.Refresh`: yes or no.
- [ ] DAO tests use the in-memory builder and close the database per test: yes or no.
- [ ] Every migration has a `MigrationTestHelper` test asserting migrated data, not only schema: yes or no.
- [ ] No Mockito/MockK import in tests: `grep -rn "mockito\|mockk" --include='*.kt' <test-root>` returns nothing.
- [ ] No Turbine import in tests: `grep -rn "turbine" --include='*.kt' <test-root>` returns nothing.
- [ ] No `open` added for tests: `grep -rn "open class\|open fun" --include='*.kt' <data-root>` returns nothing added for test subclassing: yes or no.
- [ ] Every dispatcher in production constructors is a test dispatcher under `runTest`: yes or no.
