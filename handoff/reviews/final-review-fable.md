# Final independent review — `skills-v2` Compose kit

Reviewer: independent senior Android / KMP reviewer (Fable). Scope: every file under `skills-v2/` only. No test results, earlier reviews, or `evals-v2/` material were read. API facts below were checked against live official pages on 2026-09-29; each such claim carries its URL.

**Verdict: SHIP WITH FIXES.** The architecture, rules and guard tooling are sound and unusually well cross-referenced, but the shipped templates (the code weak models copy verbatim) contain two defects that break the kit's own non-negotiables at runtime — the composition root drops the saved-state decorator that `SavedStateHandle` restore depends on, and the Android shell starts Koin in `Activity.onCreate`, which throws on the first rotation — plus eight majors, mostly template/rule contradictions. All are small, surgical fixes.

Counts: **2 blocker, 8 major, 13 minor.**

## Rules that should yield to judgement

1. **Arch rule 6 / `launchGuarded` catches only `NetworkException`; "anything else propagates as a programming defect".** Local failures are not defects: Room `SQLiteException` (disk full, constraint), DataStore `IOException`/`CorruptionException`, a JSON parse of a corrupted settings blob, a domain validation failure. Under the rule an agent must either crash the app or wrap them in a `NetworkException` (a lie the classifier docs forbid). Add a second guarded type (`AppException`/`StorageException → AppError`) or an explicit `catch` allowance in data sources with a named mapping.
2. **Data rule 8 (`expectSuccess = true`, no per-call inspection) + rule 5 (no `catch` in data).** 404-as-absent is the normal REST contract for by-identity reads and the kit's own `isMissing` state needs it (F-09).
3. **State-ownership "skip, never cancel" overlap guard.** Correct for reconcile; wrong for search-as-you-type, filter changes and any "latest request wins" flow where `flatMapLatest`/cancellation is the right tool (the paging reference already uses `flatMapLatest`).
4. **Reconcile on every `ON_START`, keyed by nav-key id.** Every foreground return re-hits the endpoint. For expensive or rate-limited APIs a freshness TTL or explicit user pull is the better default; the rule should say "reconcile *or* skip when fresh".
5. **UI rule 8: every lazy item carries `key` + `contentType`, never the index.** `contentType` on a homogeneous list is noise, and index keys are correct for immutable positional grids (calendar cells, fixed page slots) where domain identity does not exist.
6. **UI rule 10: panes only via a Navigation 3 scene strategy.** Adaptive layouts *within* one destination (a form that becomes two columns, a detail that gains a side rail) have no back-stack meaning and should not require a scene.
7. **Data rule 10: structured settings as one JSON string key; typed DataStore "not taught".** Correct for CMP `commonMain` today, but an Android-only project (a shape the kit explicitly supports) may already use Proto/typed DataStore; forcing a JSON blob loses partial updates and migrations there.
8. **Platform rule 8 default: SKIE for every new project.** SKIE lags Kotlin (max 2.4.10 while 2.4.20 is stable) and locks the toolchain; a project with fully shared Compose UI and no Swift callers pays the cost for nothing. Make it "default when Swift consumes Kotlin suspend/Flow".
9. **Arch rule 14: Koin annotations for all new code; `:core:*` Koin-free with `create<Name>()` factories.** Sensible, but the factory-plus-manual-binding pattern is ceremony for a core module with one implementation; allow a `@Module` in `:core:*` when the module is not reused outside this app.
10. **Arch rule 12 naming (`Stream` suffix mandatory; `observeX` banned).** House style, fine — but the verification greps (`observe[A-Z]`) will flag legitimate third-party calls (`LifecycleOwner.observe`, `Flow.onEach`), so the check should be scoped to repository interfaces.
11. **Code-craft KDoc "required on every ViewModel and Route".** Reasonable, but the reviewer red flag "The name is obvious; no KDoc needed on this public repository — No" pushes weak models toward the tag-restating comments the same file forbids.

## Common gaps

- **Non-network failures** have no path to `AppError` (see rule 1 above). The kit is silent on storage errors, domain validation, and what a repository `Flow` does when it throws (Room invalidation errors, SSE drops): `.catch` is forbidden as swallowing, `launchGuarded` does not apply to a collected stream, and nothing shows a stream-failure tier.
- **List destinations.** The scaffold is detail-shaped; the most common screen (a list collecting `getXStream()` via `stateIn`, with cold/reconcile handled by re-emission) has no template, and `coroutines-flow.md` shows `stateIn` only as a fragment.
- **Android application bootstrap**: no `Application` class, no `android:name`, no edge-to-edge call in the shell, although `bootstrap.md:26` says each entry point "applies platform chrome such as edge-to-edge".
- **Ktor client factory, classifier and `:core:network`** are described but not shipped (F-08); no `MockEngine` test template despite `data-testing.md` rule 1 being non-negotiable.
- **Design-system module template** holds only `HandleAppErrors`; no `AppTheme`, token, or typography file although rule 5 (tokens only) and `resources-media.md` (fonts inside a composable) presume one.
- **Platform capabilities agents hit constantly** — permissions, notifications, background work (WorkManager/BGTask), share sheets, clipboard, camera/photo picker, biometrics — appear only as one table row ("semantic port + platform implementation") with no port/adapter template.
- **Deep links**: "parse in the platform entry point and build a synthetic stack" with no example of the synthetic-stack construction or of handing a parsed key to `rememberNavBackStack`.
- **Logging, analytics, crash reporting, feature flags, app-version/force-update flow** (`UpdateRequired` exists as an error type with no handling guidance).
- **Testing**: no Compose UI test template, no repository/DAO test template, no Koin `verify()` example although `testing.md:84` requires it in `commonTest`.
- **`iosApp`**: "created from the official wizard" — no note on the Xcode framework embed step, `Info.plist` keys the interop reference says are mandatory (`ios-swift-interop.md:46-47`), or how `MainViewController` reaches Swift.
- **Existing-project migration** is well-described at policy level but has no worked example for the single most common case: adding one kit-shaped feature to a Navigation 2 + Hilt app without sharing a back stack.
