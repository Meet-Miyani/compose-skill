1. NiA proves the kit convention-plugin shape end to end: included build-logic build, one plugin per concern, thin module files, shared helpers for SDK plus Compose plus Room plus lint (SMP-01 to SMP-14).
2. Small official KMP samples ship zero build-logic: kotlinconf-app, KMP-App-Template and the CMP examples repeat target blocks inline per module, so the kit should scope mandatory convention plugins to multi-module projects and say when a single shared module may stay flat (SMP-03 vs KCONF shared build).
3. api usage in every sample matches the kit leak rule even though no sample writes the which-type comment the kit demands; the comment is kit-only ceremony worth keeping for weak models (SMP-21, SMP-22).
4. Composition-root ownership of NavDisplay is unanimous: NiA NiaApp plus kotlinconf NavHost both centralize entries, decorators and back handling (SMP-30, SMP-34).
5. The kit feature-isolation rule is stricter than NiA: NiA lets impl depend on another feature api for cross-feature keys while the kit routes through effects plus the root (SMP-24 CONFLICT).
6. Route hierarchy granularity differs: NiA uses one NavKey per feature in separate api modules while kotlinconf-app uses one global sealed AppRoute file (SMP-37 CONFLICT); the kit per-feature choice matches NiA, not kotlinconf-app.
7. DI diverges everywhere: NiA uses Hilt, kotlinconf-app uses Metro with platform graph implementations plus scoped sub-graphs, and only KMP-App-Template uses Koin DSL rather than Koin annotations (SMP-44 to SMP-48). The kit Koin-annotations decision has no official-sample precedent.
8. Test-fake and dispatcher discipline matches the kit: dedicated test-only modules, replaying hot-flow fakes with test-only setters, MainDispatcherRule plus background collection for shared flows (SMP-28, SMP-56 to SMP-58).
9. Resource discipline matches the kit direction: per-module generated resource classes, locale-qualified values, prefixed feature string keys, Android-only resources kept in shell modules (SMP-50 to SMP-53).
10. NiA ships a design-system catalog app plus generated module graphs plus dependency-guard baselines, giving the kit three enforcement precedents beyond unit tests (SMP-15, SMP-61, SMP-66).

What official samples do differently from our brief:

- No convention plugins outside NiA; the brief should state the module-count threshold where build-logic pays off.
- Cross-feature impl-to-api dependencies are normal in NiA; the brief effect-only rule needs a migration note for NiA-shaped projects.
- Single global route hierarchies exist in production KMP code; the per-feature rule needs its scalability justification restated, not assumed.
- Koin annotations appear in none of the four sources; the brief should cite Koin docs rather than samples for that decision.
- NiA ViewModels expose several parallel StateFlows instead of one UiState; the kit single-state contract is stricter than the sample and needs its own evidence row elsewhere.
- NiA keeps an app-nia-catalog module that previews the design system standalone, supporting the kit Notes plus Catalog example-domain choice.
